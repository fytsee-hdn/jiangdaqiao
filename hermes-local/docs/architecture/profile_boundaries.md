# Profile Boundaries

## Profiles

### admin

Administrative profile for system management, status observation, audit, and controlled operations. It is the only profile with `admin_capabilities: true`.

### compliance

Business profile for compliance source review and evidence drafting. It cannot inherit admin capabilities.

### service

Routing and orchestration profile for service-facing requests. It is not privileged and cannot execute admin operations for business profiles.

### reimbursement

Business workflow profile for reimbursement intake, OCR policy selection, validation, evidence, and draft outputs. It does not inherit `finance` or admin capabilities.

## Authority Rules

- Only `admin` can be admin-capable.
- Business profiles must set `admin_capabilities: false` and `may_inherit_admin: false`.
- `.hermes` runtime files cannot override source policy.
- Profiles that exist only in `.hermes` are not trusted.

## Skill Placement

Runtime skill candidates generated by agents belong in:

```text
/Users/HY-yin/.hermes/profiles/<profile>/skills/
```

Accepted reusable business skill specs may later be promoted by a separate reviewed task into:

```text
/Users/HY-yin/hermes-local/src/gsp_hermes/skills/<profile>/
```

This task creates no accepted business skills.
